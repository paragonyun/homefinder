# Home Dashboard Redesign

## 결정

메인 화면은 개발 중 데이터 보강 현황판이 아니라, 완성 후에도 계속 쓰는 **동네/권역별 후보 포트폴리오 대시보드**로 만든다.

선택안은 기존 목업의 C안이다. 홈에서 가장 먼저 보여야 하는 것은 “어떤 권역을 우선 검토할지”이고, 그 다음이 “그 권역 안에서 어떤 단지가 유망한지”다.

## 목표

- 동네/권역별 등록 단지 수, 관심 상태, 가격 범위, 강남역/여의도역 접근성을 한눈에 본다.
- 권역 카드를 클릭하면 해당 권역의 단지 검토로 자연스럽게 이동한다.
- 화면 하단 또는 우측에는 현재 우선순위 후보를 보여주되, 정교한 점수화 대신 근거 중심으로 정렬한다.
- 데이터 누락 관리는 홈의 주인공으로 두지 않고 작은 배지나 보조 문구로만 표시한다.

## 비목표

- 새 Supabase 테이블이나 migration을 만들지 않는다.
- 새 외부 API route를 만들지 않는다.
- K-apt/TMAP/국토부 동기화 로직을 변경하지 않는다.
- 홈 화면에 개발자용 “할 일 목록”이나 데이터 파이프라인 상태를 크게 노출하지 않는다.

## 데이터

기존 Supabase 테이블만 읽는다.

- `neighborhoods`: 권역 카드의 기준 단위
- `apartments`: 권역별 단지, 상태, 주소, K-apt 코드, 좌표
- `apartment_transactions`: 최근 실거래가, 가격 범위, 거래 데이터 유무
- `apartment_basic_info`: 세대수, 주차대수, 사용승인일 등 보조 근거
- `commute_times`: 강남역/여의도역 대중교통 및 자동차 접근성

Supabase가 없거나 로그인하지 않은 경우에는 기존 mock 데이터를 기반으로 예시 화면을 보여준다. 운영 데이터는 로그인 세션이 있을 때만 조회한다.

## 화면 구조

### 상단 요약

상단은 얇게 유지한다.

- 관심 권역 수
- 관심/후보 단지 수
- 실거래가가 있는 단지 수
- 접근성 데이터가 있는 단지 수

이 영역은 사용자가 현재 포트폴리오의 크기와 데이터 성숙도를 빠르게 파악하는 용도다.

### 권역 카드 그리드

홈의 핵심 영역이다.

각 권역 카드는 다음을 표시한다.

- 권역명과 설명
- 등록 단지 수, 관심/후보/보류 상태 분포
- 최근 실거래가 기준 가격 범위
- 강남역/여의도역 접근성 요약
- 대표 후보 1-2개
- 데이터가 부족한 경우 작은 배지: `가격 미확인`, `접근성 미확인`

이번 구현에서 카드 클릭은 `/neighborhoods/[id]` 이동으로 고정한다. 홈 안에는 별도 드릴다운 패널을 만들지 않는다.

### 우선순위 후보

권역 그리드 아래 또는 데스크톱 우측에 “현재 눈여겨볼 단지” 리스트를 둔다.

정렬 기준은 단순하고 설명 가능해야 한다.

- 관심 상태가 후보보다 우선
- 최근 실거래가가 있는 단지 우선
- 강남역 또는 여의도역 접근성 시간이 짧은 단지 우선
- 세대수/주차 정보가 있는 단지는 보조 가점

표시는 점수 숫자가 아니라 근거 칩으로 한다.

예: `관심`, `최근 거래 있음`, `강남 31분`, `여의도 28분`, `1,000세대 이상`

## 컴포넌트 설계

새 프론트엔드 전용 컴포넌트를 추가한다.

- `DashboardClient`: Supabase 세션과 홈 데이터를 읽는 클라이언트 컴포넌트
- `PortfolioSummaryStrip`: 상단 요약 KPI
- `NeighborhoodPortfolioGrid`: 권역 카드 그리드
- `NeighborhoodPortfolioCard`: 권역별 요약 카드
- `PriorityApartmentList`: 현재 우선순위 후보 리스트

파생 계산은 순수 helper로 분리한다.

- `buildDashboardModel`
- `summarizeNeighborhoodPortfolio`
- `rankPriorityApartments`

## 에러와 빈 상태

- Supabase 미설정: 예시 대시보드 표시
- 비로그인: 예시 대시보드와 로그인 안내 표시
- 운영 데이터 없음: “등록된 권역/단지가 없습니다” 상태 표시
- `apartment_basic_info` 또는 `commute_times` 테이블 조회 실패 중 `42P01`: 해당 보조 데이터만 비우고 홈은 계속 표시
- 일반 조회 오류: 화면 상단에 짧은 오류 메시지 표시

## 반응형

모바일에서는 한 열 카드 리스트로 보여준다.

데스크톱에서는 상단 요약, 권역 카드 그리드, 우선순위 리스트가 한 화면에서 읽히도록 배치한다. 고정 폭 테이블은 사용하지 않는다.

## 검증

- `buildDashboardModel` 단위 테스트
- 권역별 가격 범위 계산 테스트
- 접근성 데이터가 없는 단지의 배지 처리 테스트
- 우선순위 후보 정렬 테스트
- `npm test`
- `npm run lint`
- `tsc --noEmit`
- `npm run build`
- 로컬 브라우저에서 `/` 모바일/데스크톱 확인
